# EasyTier 房间联机

联机页使用 EasyTier 2.6.4 创建虚拟局域网，首次使用从 EasyTier 官方 GitHub Releases 下载约 32 MB 组件，校验官方发布的固定 SHA256 后准备。组件单独保存在 `Astral/components/easytier-2.6.4`，无需安装单独客户端或 Windows 服务。

1. 房主启动 Minecraft，进入世界并“开放局域网”。联机页自动识别端口，也可以填写本机服务端端口。
2. 点击“创建房间”，允许管理员组网助手运行。启动器和它启动的游戏保持普通权限。
3. 将六位房间号或二维码发送给好友，好友在联机页输入房间号并允许组网。
4. 连接后点击“启动并加入”；游戏已经运行时，复制地址到“多人游戏 → 直接连接”。房间内固定地址为 `10.126.126.1:35565`，由房主转发到其实际局域网游戏端口。
5. 退出房间会关闭本次组网和游戏转发端口；等清理完成后才能再开房。切换启动器页面保留连接，关闭启动器停止连接但不关闭游戏。

## 共享节点

默认节点取自明确公开的社区列表：
https://github.com/Tangent-90C/easytier-public-peers

- `udp://225284.xyz:11010`
- `wss://et.南梁.com`

来源读取日期：2026-10-27。它们不是 Astral 自营服务器，可用性和中转速度取决于提供者。双方需要相同的节点设置；可在“共享节点设置”中更换，最多三个，用英文逗号分隔。程序优先尝试 P2P，失败时可由共享节点中转。自定义节点无需账号参数，不接受带用户名或密码的 URL。

房间号在本机生成，双方通过同一独立 Astral 协议推导网络名称和密钥，不需要另行部署房间号服务器，也不使用其他启动器的私人节点。六位房间号属于便捷加入凭据，只发给可信好友，避免公开截图展示。

## 游戏环境与范围

保留服务器收藏夹、本机环境检查和手动环境码对比。双方可检查后交换 `ASTENV1` 环境码核对版本与模组。原 WebRTC 的自动环境通道不再运行。

组网仅开放固定 Minecraft TCP 端口，不配置默认出口路由、系统 DNS 或常驻服务。仍需双方游戏版本与模组兼容。此功能不改变游戏账号验证或第三方皮肤机制。

## 验证记录与限制

自动验证覆盖：房间凭据一致性和隔离、节点输入限制、组件哈希、两个真实 EasyTier 进程的本地及公共节点发现、错误房间隔离、固定端口字节转发、退出关闭监听、真实 WebView2 大小窗口界面和服务器收藏入口。

进程联网自动测试使用 `--no-tun`，没有创建虚拟网卡。管理员授权、实际 TUN 网卡路由及两台不同网络的 Minecraft 进服仍需首次交互使用验证，公共节点的发现通过不等于所有 NAT 网络均能直连或保证中转带宽。
